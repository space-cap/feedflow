# FeedFlow 상용 서비스 전환 계획

## 1. 방향

FeedFlow는 이제 MVP 검증용 앱이 아니라 실제 사용자를 받을 수 있는 상용 서비스 기준으로 개발한다. 기능 추가보다 인증, 남용 방지, 운영 자동화, 데이터 보존, 장애 대응을 우선순위에 둔다.

## 2. 현재 반영된 상용화 기반

- 로그인과 회원가입 세션 쿠키 설정을 공통 헬퍼로 중앙화했다.
- 운영 환경에서는 세션 쿠키에 `secure` 옵션을 적용한다.
- 로그인, 회원가입, 게시글 작성, 댓글 작성, 팔로우, 신고, 업로드 API에 기본 rate limit을 적용했다.
- GitHub Actions CI에서 `npm ci`, DB 초기화, seed, lint, build, API smoke test를 실행한다.
- Dockerfile과 배포 가이드를 준비했다.

## 3. 다음 우선순위

### 3.1 보안

- CSRF 방어를 추가한다.
- 로그인 실패 이력을 저장하고 계정/이메일 단위 잠금을 추가한다.
- rate limit 저장소를 메모리에서 Redis로 전환한다.
- 관리자 API 접근 로그와 감사 로그를 화면에서 조회할 수 있게 한다.

### 3.2 운영

- 구조화 로그를 도입한다.
- 에러 추적 도구를 연동한다.
- DB 백업과 복구 절차를 문서화하고 자동화한다.
- 업로드 파일을 로컬 디스크에서 오브젝트 스토리지로 분리한다.

### 3.3 제품

- 비밀번호 재설정과 이메일 인증을 추가한다.
- 팔로워/팔로잉 목록 화면과 API를 추가한다.
- 관리자 계정 정지, 해제, 제한 이력을 구현한다.
- 알림 설정과 이메일 알림을 추가한다.

### 3.4 품질

- Playwright 기반 E2E 테스트를 추가한다.
- 접근성 점검을 정례화한다.
- API 응답 시간과 에러율을 추적한다.
- 모바일 주요 화면의 시각 회귀 테스트를 추가한다.

## 4. 상용 배포 전 필수 체크

- 운영 도메인에서 HTTPS가 강제된다.
- `SESSION_COOKIE_SECURE=true`가 설정되어 있다.
- 관리자 seed 계정의 비밀번호가 교체되어 있다.
- DB와 업로드 파일이 영속 저장소에 보존된다.
- CI가 main 브랜치 병합 전 필수 상태 검사로 등록되어 있다.
- 장애 발생 시 로그, 에러, 배포 버전을 추적할 수 있다.
