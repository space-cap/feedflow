# FeedFlow 요구사항 명세서

## 1. 문서 목적

이 문서는 FeedFlow MVP 개발 범위를 명확히 정의한다. 개발 중 기능 범위가 흔들리지 않도록 사용자 역할, 핵심 기능, 제외 기능, 인수 기준을 기준 문서로 삼는다.

## 2. 사용자 역할

### 2.1 비회원

- 공개 프로필을 조회할 수 있다.
- 공개 게시글 상세를 조회할 수 있다.
- 회원가입과 로그인을 할 수 있다.
- 비공개 계정의 게시글 목록은 볼 수 없다.

### 2.2 회원

- 본인 계정을 관리할 수 있다.
- 게시글, 댓글, 좋아요, 재게시를 사용할 수 있다.
- 다른 사용자를 팔로우하거나 언팔로우할 수 있다.
- 홈 피드, 추천 피드, 프로필 피드를 볼 수 있다.
- 알림을 확인하고 읽음 처리할 수 있다.
- 사용자 또는 게시글을 신고하고 차단할 수 있다.

### 2.3 운영자

- 신고된 게시글과 사용자를 조회할 수 있다.
- 게시글을 숨김 처리할 수 있다.
- 계정 제한 또는 정지는 다음 단계 기능으로 둔다.
- 운영 조치 이력을 남긴다.

## 3. MVP 기능 요구사항

### 3.1 인증

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| AUTH-001 | 이메일, 비밀번호, 핸들, 표시 이름으로 회원가입한다. | 필수 | 중복 이메일과 중복 핸들은 가입이 실패한다. |
| AUTH-002 | 이메일과 비밀번호로 로그인한다. | 필수 | 로그인 성공 시 인증 토큰 또는 세션이 발급된다. |
| AUTH-003 | 로그아웃한다. | 필수 | 로그아웃 후 보호 API 접근이 거부된다. |
| AUTH-004 | 비밀번호 재설정 요청을 생성한다. | 필수 | 재설정 토큰이 생성되고 만료 시간이 저장된다. |
| AUTH-005 | 반복 로그인 실패를 기록하고 잠근다. | 필수 | 짧은 시간 실패가 누적되면 로그인이 제한된다. |

### 3.2 사용자와 프로필

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| USER-001 | 내 프로필을 수정한다. | 필수 | 표시 이름, 소개글, 프로필 이미지, 공개 여부가 저장된다. |
| USER-005 | 프로필 이미지를 업로드한다. | 필수 | PNG, JPEG, WebP, GIF 이미지만 2MB 이하로 저장되고 URL이 반환된다. |
| USER-002 | 다른 사용자의 공개 프로필을 조회한다. | 필수 | 핸들, 표시 이름, 소개글, 팔로워 수, 게시글 수가 표시된다. |
| USER-003 | 비공개 계정을 지원한다. | 필수 | 승인된 팔로워가 아니면 게시글 목록을 볼 수 없다. |
| USER-004 | 사용자를 차단한다. | 필수 | 차단 대상의 게시글, 댓글, 알림이 내 화면에서 숨겨진다. |

### 3.3 게시글

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| POST-001 | 텍스트 게시글을 작성한다. | 필수 | 1자 이상 500자 이하의 글만 저장된다. |
| POST-002 | 게시글 상세를 조회한다. | 필수 | 본문, 작성자, 작성 시각, 반응 수가 표시된다. |
| POST-003 | 본인 게시글을 수정한다. | 필수 | 작성자만 수정할 수 있고 수정 시간이 갱신된다. |
| POST-004 | 본인 게시글을 삭제한다. | 필수 | 물리 삭제 대신 `deleted_at`으로 소프트 삭제한다. |
| POST-005 | 게시글에 댓글을 작성한다. | 필수 | 댓글은 부모 게시글과 연결된다. |
| POST-006 | 게시글에 좋아요를 누른다. | 필수 | 같은 사용자는 같은 게시글에 한 번만 좋아요할 수 있다. |
| POST-007 | 게시글을 재게시한다. | 필수 | 같은 사용자는 같은 게시글을 한 번만 재게시할 수 있다. |

### 3.4 팔로우

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| FOLLOW-001 | 공개 계정을 팔로우한다. | 필수 | 즉시 팔로잉 상태가 된다. |
| FOLLOW-002 | 비공개 계정에 팔로우 요청을 보낸다. | 필수 | 요청 상태는 `pending`으로 저장된다. |
| FOLLOW-003 | 팔로우 요청을 승인 또는 거절한다. | 필수 | 승인 시 `accepted`, 거절 시 요청이 종료된다. |
| FOLLOW-004 | 언팔로우한다. | 필수 | 홈 피드에 해당 사용자의 신규 게시글이 더 이상 포함되지 않는다. |
| FOLLOW-005 | 팔로워/팔로잉 목록을 조회한다. | 필수 | 승인된 팔로우 관계가 커서 페이지네이션으로 반환된다. |

### 3.5 피드

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| FEED-001 | 홈 피드를 조회한다. | 필수 | 내가 팔로우한 사용자의 게시글이 최신순으로 표시된다. |
| FEED-002 | 추천 피드를 조회한다. | 필수 | 공개 게시글이 최신순 또는 단순 점수순으로 표시된다. |
| FEED-003 | 프로필 피드를 조회한다. | 필수 | 해당 사용자의 게시글과 댓글 스레드가 표시된다. |
| FEED-004 | 커서 페이지네이션을 지원한다. | 필수 | 다음 페이지 조회 시 중복 또는 누락이 없어야 한다. |
| FEED-005 | 해시태그 필터를 지원한다. | 필수 | 게시글의 `#태그`를 추출하고 탐색 화면에서 태그별 게시글을 볼 수 있다. |

### 3.6 알림

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| NOTI-001 | 좋아요 알림을 생성한다. | 필수 | 내 게시글에 좋아요가 추가되면 알림이 생성된다. |
| NOTI-002 | 댓글 알림을 생성한다. | 필수 | 내 게시글에 댓글이 달리면 알림이 생성된다. |
| NOTI-003 | 팔로우 알림을 생성한다. | 필수 | 누군가 나를 팔로우하면 알림이 생성된다. |
| NOTI-004 | 알림을 읽음 처리한다. | 필수 | 읽은 알림은 unread 카운트에서 제외된다. |

### 3.7 신고와 운영

| ID | 요구사항 | 우선순위 | 인수 기준 |
| --- | --- | --- | --- |
| MOD-001 | 게시글을 신고한다. | 필수 | 신고 사유와 대상 게시글이 저장된다. |
| MOD-002 | 사용자를 신고한다. | 필수 | 신고 사유와 대상 사용자가 저장된다. |
| MOD-003 | 운영자가 신고 목록을 조회한다. | 필수 | 상태별 필터링이 가능하다. |
| MOD-004 | 운영자가 게시글을 숨김 처리한다. | 필수 | 숨김 처리된 게시글은 일반 피드에서 제외된다. |
| MOD-005 | 운영자가 계정을 제한 또는 정지한다. | 필수 | 정지된 계정은 로그인과 콘텐츠 작성이 제한된다. |

## 4. 비기능 요구사항

### 4.1 성능

- 게시글 작성 API는 로컬 개발 환경에서 1초 이내 응답을 목표로 한다.
- 홈 피드 첫 페이지는 1초 이내 응답을 목표로 한다.
- 목록 API는 기본 20개, 최대 50개 단위로 응답한다.

### 4.2 보안

- 비밀번호는 평문으로 저장하지 않는다.
- 모든 보호 API는 인증을 요구한다.
- 관리자 API는 관리자 권한을 요구한다.
- 쿠키 세션을 사용하는 쓰기 API는 CSRF 방어를 적용한다.
- 사용자 입력은 서버에서 검증한다.
- 게시글과 프로필 텍스트 출력 시 XSS를 방지한다.

### 4.3 운영성

- 주요 API 에러는 로그로 남긴다.
- DB 마이그레이션은 버전 관리한다.
- 개발 DB는 SQLite 파일을 사용한다.
- 운영 DB 전환을 고려해 DB 접근은 ORM 또는 쿼리 계층으로 캡슐화한다.

## 5. MVP 제외 범위

- DM
- 게시글 이미지, 영상, 음성 첨부
- 고급 해시태그 트렌드
- 고급 검색
- 추천 알고리즘 개인화
- 광고
- 결제
- 외부 SNS 자동 연동
- 모바일 앱

## 6. 완료 기준

- 필수 요구사항의 API와 화면이 구현되어 있다.
- 인증, 게시글, 팔로우, 피드 핵심 흐름의 테스트가 통과한다.
- SQLite 마이그레이션과 seed 데이터가 준비되어 있다.
- 관리자 신고 확인 흐름이 동작한다.
- README에 로컬 실행 방법이 정리되어 있다.
